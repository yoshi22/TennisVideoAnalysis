# CourtLens プロダクト戦略 & 収益モデル(重要・随時参照)

最終更新: 2026-09-13。関連: `docs/development-logs/20260913_*.md`(技術経緯)。

## 全体戦略: cloud-first → データ蓄積 → edge 移行

CourtLens の CV ショット分析(ボール検出→軌跡→ショット毎の速度/コース/FH-BH/打点フォーム)の配置・収益方針。

### 配置ロードマップ
1. **フェーズ1: クラウド先行(cloud-first)** ← 現在着手
   - 動画アップロード → Modal(GPU)で全パイプライン解析 → ショットJSON返却 → アプリ表示。
   - 検証済み Python パイプラインを再利用=最速で出荷。サーバ側でモデルを高速反復。
2. **フェーズ2: 補正フライホイール(初日から並行)**
   - ユーザーが auto ドラフト(`PointRecord source:'auto', reviewStatus:'draft'`)を修正 → **人手検証済みGT**として蓄積 → 定期再学習 → モデル改善。
   - これが現状の精度限界(教師GT由来の median~5px・FH/BH unknown)を根本解決する本命。
3. **フェーズ3: オンデバイス移行(edge)**
   - モデル成熟 + 端末fps検証後、V4→CoreML/TFLite + ロジックTS移植 → **解析原価≒0・オフライン・プライバシー**。
   - 切替トリガー: 解析コストが規模で無視できない / オフライン要件 / モデル凍結可能 / 端末fps確認OK。

### なぜ「B(オンデバイス)先行」にしないか(落とし穴)
- ① 学習(補正データ収集+再学習)には**どのみちサーバが必要** → 「edge=サーバ不要」ではない。
- ② モデル未成熟の今、端末に焼くと**改良にアプリ更新が必要=反復が遅い**(クラウドは即時差替)。
- ③ **重い移植+端末fpsリスクを価値検証の前に先払い**になる。
- 結論: フライホイールは配置に依らず有効。**cloud-first で回して稼ぎ+データ蓄積 → 成熟後 edge で原価を消す**が低リスク。

## 収益モデル(ユニットエコノミクス)

### コスト(COGS)
- クラウド解析 1回 ≒ **$0.10〜0.20(約15〜30円)**(T4数分 + アップロード/保存 + コーチング生成)。
- 月間コスト/人: ライト(~4回)~90円 / ミドル(~10回)~230円 / ヘビー(~30回)~680円。

### 料金設計(目安・市場相場 ¥1,000〜2,000/月)
- **フリー**: 月3〜5解析(お試し)
- **スタンダード ¥980〜1,480**: 月10〜15解析(フェアユース上限)
- **プロ ¥2,980〜**: 上限緩め(本気/コーチ層)
- 例: ¥1,480 → Apple手数料引き手取り~¥1,000-1,180、ミドルCOGS~¥230 → **粗利~¥800/人・月(~75%)**。

### 利益率を守る/伸ばすレバー
1. **フェアユース上限 + 段階課金**(ヘビー利用を Pro 誘導=COGS頭打ち)← 最重要
2. **COGS最適化**: spot/batch GPU、ラリー区間のみ解析、解像度圧縮、結果キャッシュ → $0.05/回以下
3. **edge 移行で解析原価≒0** → 粗利が跳ね上がる(長期の利益設計)

### 注意
- 数値は採算の"型"を掴む概算。**最適価格は WTP × 対象層 × 競合 × 日本の価格感で、価格テスト(市場検証)が必要**。
- 損益分岐 = 固定費(開発/Modal基本/運用) ÷ 1人あたり粗利 = 必要契約者数。

## 意思決定サマリ(確定)
- 配置: **cloud-first**(→将来 edge)。
- 補正フライホイール: **初日から実装**(GTの質を上げ精度限界を解く)。
- 料金: **サブスク + フェアユース上限**(¥980〜1,480 スタンダード想定)。
